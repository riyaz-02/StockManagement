## Customer orders (made-to-order pieces)

The app opens the invoice with the customer, description and advance filled; staff enter the final weight and making.
- Cancel returns the advance (or part with a reason): shows as money out in the Day Book.
- App: Home card Orders; tabs Active / Overdue / Ready / Delivered / Cancelled with counts; form; detail with call, progress buttons, more advance, deliver-and-bill, cancel. Smoke 467.

## Server start-up detection fixed; release 1.4.0 (build 4)
- Why the app said "server off" while it was on: one 5-second try on the splash, two competing polling timers on the start-up screen, a proxy error counted as online, and a stale DNS answer for api.laltuguineapalace.com could hide a running server.
- App: `services/server_health.dart` is the one checker: up to 3 tries with growing limits (4/7/10 s), only "ready" counts as online, a server that answers "starting" is waited for (not shown as off), the address given by the wake Lambda is remembered on the phone and tried together with the default. The start-up screen has one timer with no overlapping checks, checks at once on opening and on returning to the app, waits up to 4 minutes.
- Server: `/health` answers 503 `{status:"starting"}` until every database is connected, then 200 `{ready:true}`; each database connection is retried up to 4 times at boot instead of the process exiting on the first failure. Local: ready about 2.6 s after launch.
- Tests: `flutter test test/server_health_test.dart` (6), smoke 467. Release APK built for production (default API_ENV=prod, signed with the release key).
