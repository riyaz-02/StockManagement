## Web portal, phase 1: the realtime spine (app + website hear changes at once)
- Backend: `app_events` (numbered log, kept 7 days) + `services/events.js`. `emit(type, data, {branchId, roles, userIds, module})` records the event and pushes it to every connected client that may see it (branch + audience rules). Emitted by: rates (`rate.changed`), stock rules (`settings.changed`), role grid / user overrides (`permissions.changed`, only to that role/person), app version (`app.update`), notifications (`notification.new`), and `data.changed {module}` from billing, credit notes, expenses, estimates, orders, old metal.
- `GET /api/live` = Server-Sent Events stream (login header, or a one-time `?ticket=` for browsers); replays what was missed (`?since=N` / Last-Event-ID); `GET /api/live/events?since=N` catch-up (with `reset` when the gap is older than the 7 days kept); `POST /api/live/ticket` (60 s, single use). Heartbeat every 25 s; max 5 streams per person; not buffered by compression. The stream does NOT count as activity for the idle-stop.

## App: faster start-up, camera-restart fix, quicker item weight entry
- **Start-up is faster**: the splash's fade-out no longer borrows the 1.2s entrance duration (now a separate 250ms `reverseDuration`); the floor delay dropped from 1.5s to 900ms; the app-update check moved off the blocking path (`LiveReactions.checkAppUpdate()`, reused from the live-push handler, runs in the background from the splash and shows its popup — still blocking if it's a forced update — after navigation instead of before it); admin/owner logins skip the permissions network call entirely on start-up (`can()` already bypasses it for them), and the remaining permissions fetch runs alongside restoring the branch choice instead of after it.
- **Fixed a real crash-on-notification bug found while touching this code**: `LiveReactions` referenced an undefined `_noContext` fallback that would have thrown if a push notification arrived before the navigator existed; it now just drops the notification in that case.
- **Camera picks no longer restart the app (as often)**: the three camera `pickImage` calls that had no `maxWidth`/`maxHeight` (add/edit item, quick add item, purchase attachment) now cap the decoded image at 1600x1600 — a high-megapixel photo decoded at full size is what spikes memory while the camera app is in the foreground and gets this app killed in the background (Android then "restarts" it instead of returning the picture). Also set `android:largeHeap="true"` in the manifest to lower the odds of that kill happening at all. This reduces how often it happens; a low-memory device can still kill any backgrounded app, and a genuine process kill loses the in-progress form the same as it did before (there is no partial-form recovery here).
- **Quicker item entry**: on the Weight step of Add stock, Net weight now sits directly beside Gross weight (the two fields nearly every piece needs); Less and Accuracy — used less often — moved to the row below.
